# L2–L5 评测指南

> 第 18 讲定义五层评测；L1 已由 `golden_set.jsonl` + `eval/run.py` 自动化。本文说明 L2–L5 如何落地。

---

## 层级总览

| 层级 | 对象 | 自动化程度 | 通过标准 |
|------|------|-----------|---------|
| **L1** | 规则引擎 R/I/W/RC/CC/RP/NL/Report/Metrics/Orchestrator | ✅ 全自动 | Golden Set 100% |
| **L2** | RAG 检索 Recall | ✅ 半自动 | Recall@5 ≥ 80% |

| **L4** | 端到端满意度 | ⚠️ 人工 | 50 case ≥ 4/5 分 |
| **L5** | 回归 | ✅ CI | 相对 baseline 下降 ≤ 5% |

import json

def compute_recall_at_k(query, relevant_ids, retrieved_docs, k=5):
    top_k = retrieved_docs[:k]
    hit = sum(1 for doc in top_k if doc['doc_id'] in relevant_ids)
    return hit / len(relevant_ids) if relevant_ids else 0.0

# 批量计算
with open('eval/rag_qa_set.jsonl') as f:
    scores = []

        item = json.loads(line)

## L3：Prompt Schema 合规

**目标**：LLM 输出符合 JSON/Markdown 模板（报告章节齐全、NL2SQL 仅输出 SQL）。

**方法**：

1. 定义 JSON Schema（`eval/schemas/report.json`）
2. 对 `report_generation` / `nl2sql` 输出跑 `jsonschema.validate`
3. 统计合规率

**现状**：规则 Agent 不依赖 LLM 时 L3 对 L1 任务自动通过；OpenAI 路径需单独抽检。

### L3 快速开始

**Step 1：创建 Schema 文件**

```bash
mkdir -p eval/schemas
```

    },

`eval/schemas/nl2sql.json`：
```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "type": "object",
  "required": ["sql"],
  "properties": {
    "sql": {
      "type": "string",
      "pattern": "^SELECT",
      "description": "仅允许 SELECT 语句，禁止 INSERT/UPDATE/DELETE/DROP"
    },
    "description": {
      "type": "string",
      "description": "SQL 用途说明（可选）"
    }
  }
}
```

**Step 2：创建校验脚本 `eval/validate_schema.py`**

```python
#!/usr/bin/env python3
"""L3 Prompt Schema 合规校验"""
import json
import sys
from pathlib import Path

def validate_report(output: str) -> bool:
    """校验报告输出是否符合 report.json Schema"""
    try:
        import jsonschema
        data = json.loads(output)
        schema = json.loads(Path("eval/schemas/report.json").read_text())
        jsonschema.validate(data, schema)
        return True
    except Exception:
        return False

def validate_nl2sql(output: str) -> bool:
    """校验 NL2SQL 输出是否仅含 SELECT"""
    try:
        import jsonschema
        data = json.loads(output)
        schema = json.loads(Path("eval/schemas/nl2sql.json").read_text())
        jsonschema.validate(data, schema)
        return True
    except Exception:
        return False

if __name__ == "__main__":
    # 示例用法
    result = validate_report('{"summary": "慢查询", "root_cause": "缺索引", "suggestions": ["建索引"]}')
    print(f"Report 合规: {result}")
```

**Step 3：运行抽检**

```bash
# 仅对 OpenAI 路径抽检（需 OPENAI_API_KEY）
python3.10 -m mysql_agent.eval.validate_schema \
  --golden-set eval/golden_set.jsonl \
  --tasks report_generation,nl2sql \
  --llm openai

# 输出示例
# L3 Schema 合规率: 24/25 = 96.0%
# 未通过: RPT002 (缺少 suggestions 字段)
```

**验收标准**：合规率 ≥ 98% 后，在 CI 中加入 `--check-schema` 门禁。

## L4：端到端人工标注

**目标**：完整诊断链路 DBA 满意度 ≥ 4/5。

**采集规范**：

| 字段 | 说明 |
|------|------|
| case_id | 如 `E2E001` |
| user_query | 原始问题 |
| context | sql / metrics / innodb_status |
| expected_tools | 应调用的工具序列 |
| human_score | 1–5 |
| reviewer | DBA 姓名 |
| notes | 误报/漏报说明 |

建议从 [eval/e2e_manual_cases.jsonl](e2e_manual_cases.jsonl) 的现有用例持续扩展。

**评审节奏**：每月抽检 10 条，双周补充 Golden Set。

## L5：CI 回归

```bash
python3.10 -m mysql_agent.eval.run_all --index-path data/vector_index
```

CI 步骤（`.github/workflows/mysql-agent-l5.yml`）：

1. `pytest` 单元测试
2. `run_all` 跑 Golden Set，与 `eval/baseline.json` 对比 `pass_rate`
3. 若 `baseline - current > 0.05` → 失败
4. CI 无 vector_index 时自动跳过 `rag_retrieval`，仅对比 **L1 层** pass_rate

更新 baseline：仅在发版分支人工确认后：

```bash
python3.10 -m mysql_agent.eval.run_all \
  --index-path data/vector_index \
  --update-baseline
```
